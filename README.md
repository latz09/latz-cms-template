# Latz Sanity Studio Template

Baseline for every client's Sanity Studio repo. Mark this repo a **GitHub
template** (Settings → Template repository) so "Use this template" is
available — though it's not used that way directly; see the workflow below.
This repo exists to be pulled *into* a freshly-scaffolded Sanity project via
`apply-template.sh`, not cloned as the starting point itself — the
`npm create sanity@latest` step is what registers a real project + gets a
current dependency install; this template just standardizes everything
after that.

## Setup workflow, per client

1. **Scaffold.** New empty folder, open in VS Code, `npm create sanity@latest`
   — pick the clean/empty starting point, not one of Sanity's example
   templates. This registers a real project (projectId, dataset, localhost
   CORS origin) and installs current dependency versions.
2. **Overlay.** Run `apply-template.sh` (keep a permanent copy of it
   somewhere on your machine, doesn't need to live in the project first).
   It pulls this repo via `degit` and overwrites Sanity's default scaffold
   with `schemaTypes/`, `structure.js`, `components/`, and `sanity.config.js`.
3. **Client specifics.**
   - Set `title` in `sanity.config.js` to the client's name (`projectId`
     is already correct from step 1 — just confirm it landed).
   - Drop `client-logo.png` and `cms-guide.pdf` into `static/` (see
     `static/README.md`).
4. **Sanity-check.** `npm run dev` once before touching the generator — if
   it boots clean with the stub pages, the overlay landed correctly.
5. **Run the schema/query/page generator.**
   - Phase 1 (schemas) → drop into *this* repo's `/schemaTypes` + `structure.js`.
   - Phase 2 (queries) → drop into the **Next.js repo's** `/data/queries`.
   - Phase 3 (pages) → drop into the **Next.js repo's** `/app`.
6. Populate real content in Studio, build components in Next.js against it.

## What's in here

| File | Regenerated by the generator? |
|---|---|
| `schemaTypes/homePage.js`, `aboutPage.js`, `servicesPage.js`, `contactPage.js` | Yes — stubs (title + SEO), replaced in Phase 1 |
| `schemaTypes/navigation.js` | Yes — generic nav, replaced with real site structure |
| `schemaTypes/testimonials.js` | Maybe — common default, drop it per-project if unused |
| `schemaTypes/contactForm.js` | No — never regenerate |
| `schemaTypes/seoSettings.js` | No — never regenerate |
| `schemaTypes/partials/seoField.js` | No — never regenerate |
| `structure.js` | Yes — fully replaced in Phase 1 |
| `components/CustomLayout.jsx` | No — no per-client edits needed |
| `components/clientLogo.jsx` | No — component's static, only the underlying image changes |

## Notes

- **No `presentationTool`/Live Preview plugin.** Not in use for client
  projects right now — deliberately left out, not an oversight. Add it back
  into `sanity.config.js` when that's live.
- **`@sanity/icons` imports:** always per-icon subpath
  (`import { HomeIcon } from '@sanity/icons/Home'`), never a combined
  named-import block from the package root — that pattern breaks on
  `@sanity/icons` v5+.
- Queries and Next.js page files are **not** part of this repo — they live
  in the separate Next.js project.
